# CTR-Calibrated RAG Ad Auction

This project extends the product-retrieval auction demo with a learned and calibrated click-through-rate (CTR) estimator.

## Pipeline

1. Parse explicit query constraints (product category, budget, RAM and storage).
2. Filter the 2,000-product advertiser catalog using only constraints actually stated by the user.
3. Compute query/product text similarity and contextual features.
4. Predict click probability with logistic regression and calibrate it using Platt-style sigmoid calibration.
5. Use the calibrated CTR estimate as the auction relevance value `q_i`.
6. Run the randomized relevance-weighted auction using `q_i * bid_i * exp(Gumbel noise)`.
7. Return a transparent sponsored recommendation with its estimated CTR.

## Important data caveat

The supplied `advertisers.csv` contains product metadata and bids, but no real impressions or clicks. Therefore `data/interactions_synthetic.csv` is generated by a documented simulation rule and all CTR predictions/metrics are **synthetic demonstration results**, not real customer CTR. Replace this file with genuine impression-level logs to make empirical claims. The model does not use advertiser bids as a CTR feature, avoiding direct bid leakage into relevance.

## Setup

```bash
python -m venv .venv
# Windows: .venv\\Scripts\\activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
```

The ZIP includes the synthetic interaction log and trained model so the demo can run immediately. To regenerate the synthetic log and retrain:

```bash
python -m src.generate_interactions
python train_ctr.py
```

To train on your own impression-level log, put it in a CSV with `query`, `advertiser_id`, and binary `click` columns, then run:

```bash
python train_ctr.py --interactions data/your_click_log.csv
```

Run an example:

```bash
python main.py "gaming laptop under ₹80000 with 16GB RAM"
python main.py "good laptop for AI/ML"
python main.py "tablet for students under ₹30000"
```

Evaluate against simple baselines:

```bash
python evaluate.py
```

## CTR model and calibration

- Base model: logistic regression on query/product similarity, lexical overlap, category match, budget compatibility, price-to-budget ratio and log price.
- Calibration: Platt-style sigmoid calibration fitted on a held-out calibration split.
- Evaluation: held-out ROC-AUC, log loss and Brier score in `models/metrics.json`.
- The synthetic impression log contains one row per query/ad impression with a binary `click` label.

For real logs, use columns `query`, `advertiser_id`, and `click` (0/1), one row per impression, then run `python train_ctr.py --interactions data/your_click_log.csv`. Keep train/calibration/test splits separate by time or query/ad group where possible to reduce leakage. Production CTR systems should also address position bias and other exposure effects.

## Paper mapping and scope

The paper's calibrated-retriever assumption relates expected CTR to the retrieval probability/relevance term `q_i`. This implementation operationalizes that idea by predicting and calibrating CTR, then passing that estimate as `q_i` to the auction. Logistic regression and Platt-style sigmoid calibration are implementation choices for this demo, not requirements imposed by the paper. The current single-slot auction and payment logic are a simplified project implementation, not a claim of complete formal reproduction of every mechanism in the paper.

## Streamlit web interface

Launch the interactive web app from the project root:

```bash
streamlit run app.py
```

The interface lets you enter a natural-language product query, choose the number of retrieved candidates and auction seed, and inspect:

- detected hard constraints (category, budget, RAM and storage),
- eligible retrieved products and their semantic similarity / calibrated CTR,
- the randomized auction ranking and selected sponsored product,
- the demo payment and generated sponsored response,
- held-out CTR-model metrics and the synthetic-data caveat.

The same `AdAuctionPipeline` used by `main.py` powers the web interface; the Streamlit app is a presentation layer and does not implement a separate auction.
